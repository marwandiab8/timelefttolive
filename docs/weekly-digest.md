# Sunday digest

Every Sunday at 7 pm Toronto time the owner can get a short look back at the week: a notification on the home-screen
app, an email, or both. It covers the Monday-to-Sunday week:
- the week in numbers: days with the boys, tracked time, targets, days with something written down;
- which targets were met and which were missed;
- one moment, from the weekly review, or else the latest thing written down that week;
- next week: which days the boys are with you, the plans placed in that time or due within eight weeks, and any
  milestone in the next four weeks.

The page is `#digest` in the app, linked from the weekly review card. Tapping the notification or the email's link
opens it too. It shows this week's digest exactly as it would go out, along with the switches.

## How it works

| Piece | Where |
| --- | --- |
| Content (pure, shared by the app and the server) | `src/utils/weeklyDigest.js` |
| Copy of that file and its imports for the functions | `functions/shared/`, generated by `scripts/copy-functions-shared.mjs` and not committed. It runs before every functions deploy (`firebase.json` predeploy), before `npm run test:functions` and before `npm run emulators`. |
| Sunday send, preview and test send | `functions/src/weeklyDigest.js`: `sendWeeklyDigests` runs on a schedule (`0 19 * * 0`, America/Toronto); `weeklyDigest` is a callable with a `preview` action and a `test` action |
| Switches and the last result | `lifeCalendars/{id}/digestSettings/owner`: `enabled`, `push` and `email` are set by the owner; `lastSentWeekEnd`, `lastResult`, `lastTestAt` and `lastError` are written by the functions. Owner only. |
| Devices for the notification | `lifeCalendars/{id}/pushTokens/{sha256 of token}`: `token`, `uid`, `platform`, `createdAt`. Owner only. |
| Notification service worker | `public/firebase-messaging-sw.js`. It only shows the notification and opens `#digest`; it does no caching. |

Safety:
- Nothing is sent until "Every Sunday at 7 pm" is ticked and at least one channel is on.
- A week is sent only once (`lastSentWeekEnd`).
- A test send is allowed at most once a minute.
- The email only goes to the owner's own verified sign-in address. There is no field for another address.
- The notification carries numbers only, never journal text or plan names, because it can show on a locked phone.
- Viewers can't read the settings or the devices.

## One-time setup (the owner does this)

### 1. Notification: the Web Push key
1. In the Firebase console, open the **timelefttolive** project, then **Project settings**, then **Cloud Messaging**.
   Under **Web configuration** and **Web Push certificates**, choose **Generate key pair**.
2. Copy the **public** key into `.env` as `VITE_FIREBASE_VAPID_KEY=...`. It is public by design, since it ships in the
   page, but `.env` stays out of git. Then rebuild and deploy hosting.
3. On the iPhone, open Time Left **from the home screen**. Push needs iOS 16.4 or later and doesn't work in Safari
   itself. Go to **Sunday digest**, then **Turn on notifications on this device**, then **Allow**.

### 2. Email: a Gmail app password
1. In the Google account that will send the email, with 2-Step Verification on, go to **Security**, then
   **App passwords**, and create one for "Time Left To Live".
2. Store the address and the password as Secret Manager secrets. Paste them when prompted; they never go in the repo
   or in chat:
   ```
   firebase functions:secrets:set DIGEST_SMTP_USER --project timelefttolive
   firebase functions:secrets:set DIGEST_SMTP_PASSWORD --project timelefttolive
   ```
   Both must exist before the functions below can be deployed.

### 3. Deploy
```
firebase deploy --only firestore:rules,hosting --project timelefttolive
firebase deploy --only functions:sendWeeklyDigests,functions:weeklyDigest --project timelefttolive
```
The second deploy creates a Cloud Scheduler job. Leave every other function out of it.

### 4. Turn it on
Open `#digest`, tick the channels, press **Send me a test now**, and check the notification and the email. Then tick
**Every Sunday at 7 pm**.

## Checking it locally
`npm run emulators`, `npm run seed:emulators`, `npm run dev:emulators`, then sign in as the demo owner and open the
review card's **Sunday digest** link.
- The preview and the test-send path run in the Functions emulator.
- Notifications can't be tried there; the page says so.
- Email reports "isn't set up on the server yet" because the emulator has no secrets. Nothing leaves the machine.
- The scheduled function is ignored there because there is no Pub/Sub emulator, so its logic is covered by
  `functions/src/weeklyDigest.test.js`.
